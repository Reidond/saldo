# Security

Saldo is designed for one owner's private deployment. Public source does not make the application or its data public.

## Boundaries

- Cloudflare Access JWT signature, issuer, audience, expiration and exact subject are checked server-side. Email headers are not identity proof.
- Every database query is owner-scoped. Mutation routes require the configured same-origin header.
- Subscription proposals are untrusted input even when generated by an AI model. Schemas, duplicate checks and atomic review transactions run on the server.
- Uploaded images are size-limited, MIME-allowlisted and checked for matching file signatures; screenshots remain transient unless a future explicit retention feature is enabled.
- AI credentials must never reach the browser, the ledger database, logs, GitHub or static assets. OAuth encryption keys belong in platform secrets outside encrypted durable storage.
- Browser demo storage holds synthetic/local records only. It is not the production ledger and must not be used as secure financial storage.

## Known pre-release limits

The live Cloudflare, ChatGPT OAuth and inference integrations require owner setup and end-to-end verification. Unit tests do not prove a live deployment is secure. Do not import confidential records until private access checks have passed. Multi-tab optimistic version conflict handling is not yet implemented; avoid editing the same record simultaneously in multiple tabs.

If you find a security issue, report it privately to the repository owner. Do not include real financial records, tokens or screenshots in public issues.
